# Standalone browser previews / 独立前端预览

Build the same preview engines as one main JavaScript file or split modules,
with an optional external archive engine in either build. Both
include Vue, styles, PDF/iWork workers and the document, image/RAW and STEP WASM
engines. No conversion server or host Vue installation is needed.

For iOS and Android application embedding, the [source SDKs](../../sdk/README.zh-CN.md)
wrap this same runtime in native views, with local file loading and lifecycle callbacks.

Version **0.3.0** adds the mobile source SDK integration, encrypted / solid / multipart
RAR and 7z previews, Office attachment previews, smaller embedded WASM, shared ZIP
loading and the default `FiLens © IceWhale` watermark. The optional archive engine
and its worker stay external in both runtime builds.

Version 0.2.0 adds 28 toolbar languages, application-icon previews and the
runtime fixes used by CLI 0.5.0's offline HTML preview. It uses native HEIC/HEIF decoding first, with a small dedicated WASM
decoder as fallback. MOV plays through browser codecs.
Applications can supply an optional `mediaConverter` for unsupported MOV codecs.
Both builds preserve the same image and video support boundaries.
For optional local MP4/MOV recovery, pass `browserMedia: true` to `createPreview`.
It tries native playback first, then bounded remuxing or necessary WebCodecs AVC
processing, and never calls `mediaConverter` for video in this mode.
[Browser-only media scope and validation](../../docs/browser-media-engine.md).

```sh
npm install filens-preview
```

```js
import { createPreview } from 'filens-preview';
// Or: import { createPreview } from 'filens-preview/all-in-one';
```

The npm package includes both runtime directories, TypeScript declarations and third-party notices.
Deploy `node_modules/filens-preview/dist/split/` or `dist/all-in-one/` for direct browser use.

The split build registers lightweight format routes first, then imports the
matching renderer when a file opens: PDF, DOCX, XLSX/CSV, PPTX, iWork, CAD, 3D,
archives, ebooks, mindmaps, diagrams, codecs and panorama/RAW. Text, HTML and
ordinary images share a native driver module. Vue and compression are shared;
format engines and WASM remain cached after first use. Nested archive entries
follow the same loading path. Deploy the entire directory so every format stays
available, including offline. The all-in-one build still contains every engine
in one main file. [Measured loading sizes](../../docs/assets/dsh-plugin/format-loading.json).

## Build and use

```sh
npm ci
npm run build:wasm
npm run build:preview
```

Deploy the entire `packages/preview/dist/split/` directory, or
`dist/all-in-one/filens.js` with the archive sidecars when needed. The following
table is generated by `npm run report:preview-sizes` from exact byte measurements.

<!-- preview-runtime-sizes:start -->
| Runtime | Raw MB | gzip MB | Brotli MB |
| --- | ---: | ---: | ---: |
| Split main runtime | 18.10 | 6.11 | 4.73 |
| All-in-one main JS (precompressed) | 7.26 | 3.99 | 3.85 |
| Optional archive WASM + worker (either build) | 1.17 | 0.46 | 0.36 |
| Split with archive assets | 19.27 | 6.57 | 5.09 |
| All-in-one with archive assets | 8.43 | 4.45 | 4.21 |
<!-- preview-runtime-sizes:end -->

The all-in-one build includes ready-to-serve `filens.js.gz` (Zopfli) and
`filens.js.br` files, each capped at **4,000,000 bytes** by the build. Configure
your server to serve them for `filens.js` with the matching `Content-Encoding`
and JavaScript content type; for example, use `gzip_static on` in nginx.
Ordinary dynamic gzip of the JS is about 4.02 MB; use the supplied gzip file to
meet the 4 MB transfer budget. Optional archive assets and notices are separate.

The merged runtime packs static WASM, worker data and long strings with a shared
LZMA dictionary and restores them with a small inline WASM decoder. It preserves
the synchronous ESM exports and ES2020 bundling, with no JavaScript evaluator or
additional module request. The build checks every restored asset byte and emits
`asset-packing.json` with hashes, sizes and the compressed artifact checks.
Restoration adds work during module initialization; use the split build when
startup latency and selective engine loading matter most.

These are current source build measurements (MB = 1,000,000 bytes), including
application icons, optional Office decryption and 28 locale dictionaries. The
archive engine always stays external, including all-in-one builds, and is loaded
only for RAR, 7z or multi-volume ZIP. Ordinary ZIP and ZIP-based document formats
share the existing JSZip/fflate dependencies. The extraction-only engine uses
-O3 and LTO, retains encryption and all supported decoders, and shares its compiled
WASM module between fresh per-operation workers. iWork uses the ordinary ZIP
reader without duplicating the ZIP encryption library. The totals in the table
include the optional archive assets and exclude notices.
The npm package contains both directories, including notices, types and
documentation. Packed and installed bytes are recorded for each release.
[Package measurements](https://github.com/IceWhaleTech/filens/blob/main/docs/preview-package-sizes.json).

Both directories contain an `index.html` with a local file picker. Serve either
directory over HTTP(S). To integrate into another page:

```html
<div id="preview" style="height: 80vh"></div>
<script type="module">
  import { createPreview } from './split/filens.js';
  // Or: import { createPreview } from './all-in-one/filens.js';

  const viewer = createPreview('#preview', {
    src: './report.pdf',
    name: 'report.pdf',
    onError: error => console.error(error)
  });
  // File / Blob / Uint8Array sources also work; supply a name or extension.
  // viewer.update({ src: anotherFile, name: anotherFile.name });
  // viewer.destroy();
</script>
```

`createPreview()` mounts the shared `Preview` component and returns `update()`,
`getState()`, `setScale()`, `fullscreen()` and `destroy()`. Pass `toolbar: false`
to use your application’s toolbar, then call these controls on the returned viewer. Options include `src`, `name`, `extension`, `toolbar`, `converter`, `panoramaProcessor`,
`resourceResolver`, `fontResolver`, `onRendered` and `onError`. The default converter
uses the bundled frontend WASM engines. Use [`@filens/vue`](https://github.com/IceWhaleTech/filens/tree/main/packages/vue) for
direct Vue component integration.

Previews display a translucent `FiLens © IceWhale` watermark at the bottom right,
including when the toolbar is hidden and in preview fullscreen mode.

Split chunks can range from a few KB to hundreds of KB after compression. Those
figures exclude shared dependencies and engines; a chunk is not a complete
per-format download. The all-in-one file embeds CSS and document/image engines.
The RAR/7z engine and its worker are always separate files, never base64-embedded;
deploy both sidecars alongside the main JS to enable RAR, 7z and multi-volume ZIP.
They can be omitted when those formats are not required.
A separate notices file accompanies
both builds and should be distributed with them. [Exact measurements](https://github.com/IceWhaleTech/filens/blob/main/docs/preview-build-sizes.json).

Single-file embedding still requires browser support for WebAssembly and workers.
Pages with a Content Security Policy must permit the generated inline styles,
`blob:` workers, and `blob:` / `data:` WASM connections. WASM compilation needs
`'wasm-unsafe-eval'`; packing adds no JavaScript `'unsafe-eval'` requirement.
Use an HTTP(S) server for module imports, rather
than opening the module-importing `index.html` as a `file:` URL. The CLI's
self-contained HTML embeds the module instead and supports `file:` URLs.
RAR, 7z and multi-volume ZIP require the separate archive assets over HTTP(S);
CLI HTML shows a `--mode serve` fallback for them instead of embedding the engine.
The supported formats and fidelity
limits are shared with the [demo](https://github.com/IceWhaleTech/filens/blob/main/docs/support-matrix.md).

## Languages and application icons (0.2.0)

Preview toolbars, common prompts and model controls include the same 28 locale
codes as ZimaOS. Pass `locale: 'zh_CN'` (or `zh-CN`); omit it for browser language
detection. Switch language with `viewer.update({ locale: 'de_DE' })`. Optional
`messages: { Next: 'Forward' }` overrides English source phrases per instance.
Both split and all-in-one builds contain these dictionaries for offline use.
See the [locale list and API notes](../vue/README.md#languages-source-build).

APK/IPA packages open as ZIP-compatible archives with directory browsing and
entry previews. Windows EXE/DLL/MUI/MUN resource files can be previewed as
application icons using the included WASM converter. The converter also exposes
APK/IPA icon extraction for explicit requests. Icon extraction supports compiled
Android icon resources, XML/binary iOS plist metadata, iOS CgBI PNGs,
and Windows PNG/DIB icon frames. These additions are included in 0.2.0.
See the [supported icon representations
and limits](../vue/README.md#application-icons-source-build).

The browser file picker accepts multi-volume RAR (`.part01.rar` or `.rar`/`.r00`),
7z (`.7z.001`) and ZIP (`.zip.001` or `.z01`/`.zip`) archives. Select every part
together; picker order does not matter. Password prompts and nested previews
work across the parts. Missing first/intermediate volumes identify the filename;
the engine validates completeness. Limits are 256 parts and 512 MiB compressed
input per set, with 128 MiB per expanded entry. Both HTTP(S)-served builds support
this workflow with local archive sidecars; no remote service or CDN is used.
Programmatic callers supply the other
parts as `src.archiveVolumes: [{ name, source }]`; see the
[core API example](../core/README.md).

The split build loads `converter-office.wasm` only when an encrypted Office
document has a supplied password; a password prompt alone does not download it.
The all-in-one file includes the combined core with Office decryption,
PostScript and graphics conversion, avoiding duplicate WASI and parsing code.
Its static assets share a solid LZMA stream, restored during initialization;
the original WASM is then compiled when needed. HTTP split assets remain ordinary
WASM and use streaming compilation with the correct MIME. Historical core-only
comparisons are in the [same-source measurements](../../docs/converter-size-impact.md); current
main-runtime bytes are in `asset-packing.json` and the
[format package audit](../../docs/format-package-sizes.md).

## CLI preview

CLI 0.4.0 includes `preview`. The first preview downloads the optional frontend
package into the writable versioned cache; subsequent previews work offline.
You can install it ahead of time:

```sh
npm install -g filens-cli
filens setup-preview
filens preview report.pdf
filens preview report.pdf --no-open --json
```

`filens-cli-lite` supports the same preview command without OCR models. Frontend
resources are separate from the base CLI installation. For a source build:

```sh
npm run build:wasm
npm run build:agent:preview
npm run filens -- preview report.pdf

# Or run the freshly built binary directly
./dist/filens preview drawing.step
./dist/filens preview report.pdf --no-open --json
```

CLI 0.4.x used a loopback HTTP server. **CLI 0.5.0 defaults to a self-contained
HTML instead**: the shared all-in-one frontend runtime and a
copy of the selected file are embedded, the browser opens a `file:` URL, and the
CLI exits. No HTTP server is started. Parsing, conversion and rendering happen
in the browser, with no external runtime dependencies. The page checks WASM and
local Worker support and displays compatibility instructions on failure. It also
includes a GitHub link and third-party notices. Browser launch success does not
certify rendering; the CLI cannot automatically detect every browser failure.

```sh
# Generate and open an offline HTML, or save it without opening a browser
filens preview report.pdf
filens preview report.pdf --output report-preview.html --no-open
filens preview report.pdf --no-open --json

# Compatibility mode: serve only on this machine; Ctrl-C stops it
filens preview report.pdf --mode serve
```

HTML mode returns a `file:` URL and a filesystem `path`; the command exits even
with `--no-open --json`. Default HTML files remain in the system temporary
directory so the browser can finish loading after CLI exit. **The HTML contains
the original file bytes**; delete it when no longer needed. `--output` never
overwrites existing files. Base64 embedding adds about one third to the source
file size, plus the runtime and notices. Prefer HTTP mode or the browser file
picker for very large files. The HTML's Content Security Policy blocks external
connections and resource loads; linked images/fonts are unavailable unless
embedded or supplied locally. The GitHub link opens only when clicked.

On `file:` pages PDF.js uses its supported main-thread worker implementation to
avoid opaque-origin module-worker restrictions in WebKit. Large PDFs can occupy
the UI thread; HTTP mode keeps the usual worker loading path.
WebKit currently cannot load the embedded iWork parser worker from a `file:`
page. Its error panel offers `--mode serve`; the same Keynote sample was verified
with the split runtime in that compatibility mode. Chromium and Firefox support
the tested iWork HTML previews directly.

`--mode serve --no-open --json` retains the previous URL/server lifecycle. Its
command keeps running until Ctrl-C. `--port` implies serve mode unless an explicit
`--mode` is given. To choose a port or built runtime:

```sh
# Choose a port or another built runtime (including the all-in-one build)
filens preview report.pdf --mode serve --port 8080 --assets /path/to/preview/dist/all-in-one
```

`FILENS_PREVIEW_DIR` overrides the default `<binary-directory>/preview` asset
directory. An asset directory can be the package's `dist/` root or a specific
`split/` / `all-in-one/` directory; HTML mode needs the all-in-one runtime (a
`split/` directory also works when its `all-in-one/` sibling is present).
Source npm packaging can include the assets with
`node scripts/package-agent-npm.mjs --with-preview`. These optional resources
include both split assets and the all-in-one runtime, measured separately from
the document-reading CLI.

The server exposes one selected file, not its parent directory. Models or media
with external sidecars need a supported ZIP bundle or a host-provided resource
resolver; arbitrary adjacent files are not served. Binary media responses support
byte ranges. The listener checks the Host and Origin, scopes routes to a random
session path, and rejects directory traversal. CLI preview has been exercised on
macOS; Windows/Linux browser launching still needs native validation.
