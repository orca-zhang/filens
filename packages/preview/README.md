# Standalone browser previews / 独立前端预览

Build the same preview engines as one main JavaScript file or split modules,
with an optional external archive engine in either build. Both
include Vue, styles, PDF/iWork workers and the document, image/RAW and STEP WASM
engines. No conversion server or host Vue installation is needed.

For iOS and Android application embedding, the [source SDKs](../../sdk/README.zh-CN.md)
wrap this same runtime in native views, with local file loading and lifecycle callbacks.

Version **0.3.7** displays only `FiLens` in the preview watermark, including fullscreen and hidden-toolbar views.

Version **0.3.0** adds the mobile source SDK integration, encrypted / solid / multipart
RAR and 7z previews, Office attachment previews, smaller embedded WASM, shared ZIP
loading and the default `FiLens` watermark. The optional archive engine
and its worker stay external in both runtime builds.

Version 0.2.0 adds 28 toolbar languages, application-icon previews and the
runtime fixes used by CLI 0.5.0's offline HTML preview. It uses native HEIC/HEIF decoding first, with a small dedicated WASM
decoder as fallback. MOV plays through browser codecs.
Applications can supply an optional `mediaConverter` for unsupported MOV codecs.
Both builds preserve the same image and video support boundaries.
For optional local MP4/MOV recovery, pass `browserMedia: true` to `createPreview`.
It tries native playback first, then bounded remuxing or necessary WebCodecs AVC
processing, and never calls `mediaConverter` for video in this mode.
[Browser-only media scope and validation](../../docs/browser-media-engine.md).

```sh
npm install filens-preview
# Smaller package with only the lazy-loaded split runtime:
npm install filens-preview-split
```

```js
import { createPreview } from 'filens-preview';
// Or: import { createPreview } from 'filens-preview/all-in-one';
```

The npm package includes both runtime directories, TypeScript declarations and third-party notices.
Deploy `node_modules/filens-preview/dist/split/` or `dist/all-in-one/` for direct browser use.
The split-only package contains the same split runtime and declarations without the all-in-one build. Both packages include on-demand WASM assets and third-party notices.

The split build registers lightweight format routes first, then imports the
matching renderer when a file opens: PDF, DOCX, XLSX/CSV, PPTX, iWork, CAD, 3D,
archives, ebooks, mindmaps, diagrams, codecs and panorama/RAW. Text, HTML and
ordinary images share a native driver module. Vue and compression are shared;
format engines and WASM remain cached after first use. Nested archive entries
follow the same loading path. Deploy the entire directory so every format stays
available, including offline. The all-in-one build combines the runtime in one
main file and loads the archive and XLSX regex assets on demand. [Measured loading sizes](../../docs/assets/dsh-plugin/format-loading.json).

```sh
npm ci
npm run build:wasm
npm run build:preview
```

The all-in-one build includes ready-to-serve `filens.js.gz` (Zopfli) and
`filens.js.br` files, each capped at **4,000,000 bytes** by the build. Configure
your server to serve them for `filens.js` with the matching `Content-Encoding`
and JavaScript content type; for example, use `gzip_static on` in nginx.
Ordinary dynamic gzip of the JS is about 4.01 MB. Serve the supplied gzip file
to meet the 4 MB transfer budget. The default GitHub all-in-one ZIP omits both
sidecars to reduce its download size; the same release provides an optional
`filens-preview-<version>-all-in-one-precompressed.zip` to overlay beside
`filens.js` for static hosting. The already published 0.3.7 npm tarball keeps
its existing contents, while new npm tarballs omit the sidecars. CDNs such as
jsDelivr negotiate compression automatically. For self-hosted npm installs,
enable dynamic compression or download the optional sidecar ZIP.
Optional archive assets and notices are separate.

The merged runtime packs static WASM separately from long strings. Resources of
100 KB or more, including the PDF, iWork and media workers, each have their own
LZMA group. A small inline WASM decoder restores ordinary resources at startup;
worker sources and Blobs are created on demand, and WASM on its first use. It preserves
the synchronous ESM exports and ES2020 bundling, with no JavaScript evaluator or
additional module request. The build checks every restored asset byte and emits
`asset-packing.json` with hashes, sizes and the compressed artifact checks.
Restoration adds work during module initialization; use the split build when
startup latency and selective engine loading matter most.
The source reader uses a direct byte loop when native Base64 decoding is absent
and verifies CRC-32 eight bytes at a time. Original asset bytes and integrity
checks are preserved. [Startup measurements](../../docs/packed-startup-performance.zh-CN.md).
Grouping defers approximately 9.3 MB of WASM restoration for text and ordinary
PDF previews. It still downloads the full single file; the split build also
defers downloading unused engines. [Grouped startup measurements](../../docs/grouped-startup-performance.zh-CN.md).
Independent workers further reduce text startup work; PDF reuses its deferred
worker URL across sessions. [Worker startup measurements](../../docs/worker-startup-performance.zh-CN.md).
Each embedded WASM file now restores independently on first use, so HEIF and
STEP do not unpack unrelated engines. [WASM startup measurements](../../docs/wasm-startup-performance.zh-CN.md).
Resource groups share one lazily compiled decoder module. [Decoder startup measurements](../../docs/decoder-startup-performance.zh-CN.md).
For offline HTML, opaque-origin HEIF workers receive the embedded WASM bytes
from the document; ordinary HTTP workers retain their URL loading path.

These are current source build measurements (MB = 1,000,000 bytes), including
application icons, optional Office decryption and 28 locale dictionaries. The
archive engine always stays external, including all-in-one builds, and is loaded
only for RAR, 7z or multi-volume ZIP. Ordinary ZIP and ZIP-based document formats
share the existing JSZip/fflate dependencies. The extraction-only engine uses
-O3 and LTO, retains encryption and all supported decoders, and shares its compiled
WASM module between fresh per-operation workers. iWork uses the ordinary ZIP
reader without duplicating the ZIP encryption library. The totals in the table
include the optional archive assets and exclude notices.
`filens-preview` contains both directories; `filens-preview-split` contains only
the split directory. Both include notices and declarations. Packed and
installed bytes are recorded in the [release size report](../../docs/preview-sizes.md).
[Package measurements](https://github.com/orca-zhang/filens/blob/main/docs/preview-package-sizes.json).

Both directories contain an `index.html` with a local file picker. Serve either
directory over HTTP(S). To integrate into another page:

```html
<div id="preview" style="height: 80vh"></div>
<script type="module">
  import { createPreview } from './split/filens.js';
  // Or: import { createPreview } from './all-in-one/filens.js';

  const viewer = createPreview('#preview', {
    src: './report.pdf',
    name: 'report.pdf',
    onError: error => console.error(error)
  });
  // File / Blob / Uint8Array sources also work; supply a name or extension.
  // viewer.update({ src: anotherFile, name: anotherFile.name });
  // viewer.destroy();
</script>
```

`createPreview()` mounts the shared `Preview` component and returns `update()`,
`getState()`, `find()`, `findNext()`, `setWrap()`, `setScale()`, `fullscreen()` and `destroy()`. Pass `toolbar: false`
to use your application’s toolbar, then call these controls on the returned viewer. Options include `src`, `name`, `extension`, `toolbar`, `converter`, `panoramaProcessor`,
`resourceResolver`, `fontResolver`, `onRendered` and `onError`. The default converter
uses the bundled frontend WASM engines. Use [`@filens/vue`](https://github.com/orca-zhang/filens/tree/main/packages/vue) for
direct Vue component integration.

Once a PDF is ready, `await viewer.find('literal phrase')` searches all pages,
including pages outside the rendered viewport. `viewer.findNext()` advances to
the next match and `viewer.findNext(true)` goes backwards, wrapping at either
end. `viewer.find('')` cancels and clears the search. The PDF find control also
opens with Ctrl/Cmd+F while the PDF viewport has focus, supports Enter/Shift+Enter
and Escape, and follows the host locale. `getState()?.search` reports the query,
active match, total, pages scanned, progress and any error/truncation. Matching is
case-insensitive literal text; line endings between PDF text items act as spaces.
Results are session-local and capped at 10,000 with explicit incomplete status.
Replacing or clearing a query cancels the current page text stream, even while it
waits on remote content. The open document can still use pending byte ranges for
rendering. Closing or replacing the document cancels its pending reads. Image-only
PDFs need OCR before they contain searchable text. These controls are in the
current source and require a new runtime build; published preview 0.3.8 predates them.

Virtual PDFs mount page containers, canvases and text layers around the visible
viewport. Pages use the first page's dimensions until PDF.js reports their own.
For extremely tall documents, the scroll track covers the full document while
the mounted pages keep the current zoom. `virtual: false` renders the complete
document for printing.

Virtual previews accept an HTTP(S) PDF URL directly. For files larger than
128 KiB, PDF.js can request byte ranges when the server sends a valid
`Content-Length`, advertises `Accept-Ranges: bytes`, and serves identity-encoded
bytes with matching `206` and `Content-Range` responses. Cross-origin servers
must allow the preview origin and expose `Accept-Ranges`, `Content-Range`, and
`Content-Encoding` when present. PDF.js streams the ordinary response when
range support is unavailable. Closing or replacing the preview cancels pending
reads. PDF.js can read widely scattered objects during initialization, and a
full-document search can load the remaining bytes.

Virtual previews of File/Blob inputs larger than 128 KiB supply PDF.js with
byte slices through `FileReader`. Replacing or closing the preview aborts active
reads, and password retries reopen the file through the same range interface.
Small files and non-virtual previews use a full read. For range-loaded documents
larger than 16 MiB, the PDF.js worker stores the chunks as they arrive. The
document layout determines how many bytes the worker reads before the first
page. Recovery and explicit full-document reads can assemble a contiguous copy.

Text/code previews also implement `find()`/`findNext()` with literal, case-insensitive
matching, a 10,000-match cap, and cancellation on a new query, replacement or
destruction. `viewer.setWrap(true)` wraps source lines while preserving syntax
spans and aligned logical line numbers. These previews share the localized find
controls and keyboard shortcuts with PDF. UTF-8/UTF-16 BOMs and declared MIME
charsets are honored; malformed byte sequences warn and binary/unsupported
encodings fail explicitly. Text search reports one source document in the shared
page-count fields. Above 500 logical lines, previews render visible/nearby
128-line blocks, measuring wrapped heights and retaining the logical reading
position across resize/wrap changes. Search navigates to unmounted content.
Focus the text viewport and press Ctrl/Cmd+A before copying to include the full
original source, including its line endings. Native drag-selection covers mounted
content; pass `virtual: false` when the host needs the complete DOM or native
browser find. Full decoding and line indexes remain in memory; an individual
extremely long logical line still incurs layout cost, and unread dimensions are
estimated until measured.

Current-source EPUB/CBZ previews index the book before opening only the selected
chapter/page and its referenced assets. Page turns discard superseded reads and
release the previous chapter's owned URLs. The previous frame stays visible while
a chapter loads; `getState()?.chapterLoading` reports that work while ordinary
navigation remains available. EPUB 3 navigation and EPUB 2 NCX supply chapter labels;
without them, unread chapters use filenames until opened.

The EPUB table of contents keeps nested sections and links to chapter fragments.
Enter a chapter or page number to jump directly in EPUB or CBZ. Choose the
publisher style, light, sepia or dark in the reading theme menu. The selection
follows chapter changes, and theme changes preserve scroll position in
same-origin frames. Those EPUB frames also keep links between spine chapters
inside the reader. An opaque share viewer supports the contents and theme menu.
Changing the theme there reloads the chapter frame from the existing markup and
returns to the selected contents anchor when available.

EPUB/CBZ previews read the tail and central directory of single-volume ZIP and
ZIP64 archives using HTTP ranges or, for large local files, Blob slices. The
index handles Info-ZIP Unicode paths and CP437 filenames. After indexing, the
viewer reads the selected entry and its referenced assets. Changing chapters
cancels pending HTTP reads. The server must return identity-encoded `206`
responses with matching `Content-Range` headers. Cross-origin servers must
expose `Content-Range`, and should expose `ETag` and `Content-Encoding` when
present. Unusable HTTP ranges and ZIP layouts handled by the compatibility reader
fall back to a full read. Multi-volume ZIPs require the archive viewer and all
parts. The `@filens/books` functions `loadEpubBook()` and `loadCbzBook()` retain
complete-book extraction.

Current-source Numbers previews also reuse the XLSX/CSV row and column windows
for large tables, including picture cells. Variable row heights preserve source
minimums and measure loaded images; horizontal scrolling and font refresh retain
known heights. Several tables can share one viewport; resize remeasures cells
while preserving the logical reading row, and late layout changes retain the
bottom position. `virtual: false` retains incremental row loading. The full
parsed model stays resident; this reduces rendered DOM rather than parsing memory.

Native XLSX previews can read remote ZIP packages through HTTP byte ranges and
large local files through Blob slices. The workbook and attachment list share the
ZIP index, and opening an attachment reads its payload. An ordinary HTTP response
or an encrypted Office envelope can require the full package. The viewer loads
all worksheets to resolve cross-sheet formulas.

Large DEFLATE-compressed XLSX worksheets decode and parse XML in row batches of
about 512 Ki characters. Numeric and shared-string cells retain direct parsing,
and formulas, row sizes, merges and conditional rules retain worksheet scope.
The preview can yield between batches to respond to cancellation. Oversized
rows, unsupported XML and ZIP compatibility paths can require buffered parsing.
[Worksheet measurements](../../benchmarks/frontend/2026-11-25/xlsx-worksheet-streaming.json).

Large DEFLATE-compressed shared string tables stream from native ZIP
decompression into batches of the same target size, retaining string indices,
rich runs and cross-sheet formula values. The compressed entry, string index
and full workbook cell model still require memory. ZIP compatibility paths and
oversized items may need the expanded XML. XML outside the supported framing or
with a potential document-wide entity limit overflow goes through the general parser.
[Shared string measurements](../../benchmarks/frontend/2026-11-25/xlsx-shared-string-streaming.json).

XLSX and Numbers grids preserve rectangular merged cells across both window
boundaries. XLSX anchor values/fonts/formulas and Numbers anchor text/pictures
survive offscreen origins.
Only mounted rows/columns receive native spans; content keeps its source offsets
so scrolling through a large merge does not repeat its heading. Multi-row merged
pictures fit the source row area. Incremental Numbers batches retain earlier
anchors. Compact workbook hosts fit their available height. Source alignment,
borders and full styling remain partial for XLSX.

Numbers grids render parsed rich runs (fonts, sizes, emphasis, colors and links),
paragraph spacing/wrapping/padding/alignment, solid/gradient/basic pattern fills
and per-side borders through the shared core. Loaded font mappings reach visible
runs; font probes are shared only within each synchronous visible-row batch.
Merged text retains its source alignment, gradients retain source coordinates,
and clipped fragments omit interior borders. Unstored blank cells inherit source
fills and borders, including row and column overrides, banding and header and
footer styles. The grids resolve their paint when a row batch renders, keeping
the workbook model sparse. Source column widths stay
fixed in both virtual and incremental grids, including narrow tables and columns
wider than the viewport. Horizontal windows, spacers, merged text and gradients
use cumulative source widths. Resizing retains those widths and the reading row.
Omitted style metadata and advanced effects remain partial. Picture cells keep
fitted image previews. CSV keeps default column widths.

XLSX grids retain explicit column ranges, `defaultColWidth` and `baseColWidth`,
including the implicit eight-character base when no size metadata is stored.
Widths use the Normal style's font, point size and maximum digit advance with the
ISO 29500 character-to-pixel calculation. Rendering measures the available font;
font refresh remeasures widths while preserving the logical reading column and
position within it. The parser retains raw metadata alongside a 7px digit-width
baseline for hosts without canvas metrics. Metadata-only parsing keeps numeric
worksheets on their fast path; source ranges never create cell objects or extend
the sheet beyond its cells/merges. Normal fonts used only for sizing participate
in font loading, with mappings isolated between cached previews. Saved formula
views show stored and shared expressions at twice the normal pixel column widths.
Missing source fonts and live column best-fit remain fidelity limits.
Layout-height measurement keeps the final Excel row
reachable when far-offscreen client rectangles lose precision. Standalone
workbook grids compress unmounted row spacers when the sheet exceeds the
browser's scroll height limit. Visible rows keep their layout height.

XLSX uses default and per-row heights saved in the worksheet. Fixed rows clip
text and merged content within their source height. Automatic rows use the saved
height as their minimum and grow for mounted cell content. Sparse height indexes
and viewport-based windows support compact rows through the final Excel row.

XLSX and Numbers grids collapse saved hidden rows and columns. Scrolling and
merged spans count visible tracks while labels and merge anchors retain their
source coordinates. XLSX honors hidden-by-default rows (`zeroHeight`) and
preserves hidden formula dependencies. Numbers applies saved visibility in both
virtual and incremental views, including after font refresh.

XLSX also renders source font size, emphasis, underline and strike, RGB/theme/indexed
colors, solid and basic patterned or gradient fills, four-sided borders and explicit
alignment. Visible blank cells inherit row, column or default formats without
creating stored cells. Wrapped text grows individual rows with sparse height
measurements. Merged fragments retain the anchor's formatting, source alignment and
gradient coordinates. Shared and inline rich strings preserve per-run fonts,
sizes, emphasis, colors, decorations and baseline shifts. Run faces participate
in font diagnostics and host font loading. Diagonal and continuation-cell borders
and advanced alignment remain partial or unavailable.

Conditional formatting applies value comparisons, supported formulas, text
matches, blanks and errors to visible cells and merged anchors. Rules honor source
priority and stop-if-true, and use the differential fill, emphasis, color, border
and number-format declarations. Relative formulas share the worksheet formula
engine. Two- and three-color scales and legacy or Office 2010 data bars resolve
numeric, percentage, percentile and supported formula thresholds. Sparse range
scans include offscreen values and count overlapping areas once. Rankings and
exact percentiles use a temporary numeric buffer. Data bars retain signed axes,
direction, source colors, borders, and the layout of clipped merged cells.
The preview supports all base and Office 2010 icon families, including reversed
order, inclusive and exclusive thresholds, custom or omitted icons, and optional
formula gates. Icon-only mode hides the rendered value while retaining its
accessible text. The browser approximates Excel's icon graphics and data bar
gradients.

Top and bottom rules include every value tied at the cutoff. Percentage ranks
round down using the number of numeric cells. Above and below average rules
support inclusive bounds and population standard deviations. Duplicate and unique
rules compare typed values, with case-insensitive whole-cell wildcards for text.
They skip empty and error cells. Date-period rules use the viewer's local date,
Sunday-based weeks, and the workbook's 1900 or 1904 date system. Locale-specific
text matching and further extensions are pending.

XLSX displays built-in and custom number formats for dates, elapsed time,
percentages, currencies, fractions and scientific notation. It supports the 1900
and 1904 date systems, cached or evaluated numeric formulas, and custom sections
for positive, negative, zero and text values. Formatting happens when a cell is
mounted, so formulas retain their raw inputs and results. Numeric-looking strings,
booleans and errors retain their source types. Unsupported format codes that fail
to parse keep the raw value. Recognized Windows locale IDs in date format
sections, such as `[$-40C]`, select Gregorian month and weekday names and AM/PM
markers using the browser's locale data. Each active section can apply a named
color or a `Color1`–`Color56` entry from the saved workbook palette. Explicit
conditional font colors take priority. Separators, non-Gregorian calendars,
system date/time directives, negative date/time display and width-driven
accounting padding remain limited.

For XLSX formulas without a cached result, the preview supports arithmetic,
comparisons, percentages, `SUM`, `AVERAGE`, `MIN`, `MAX`, `COUNT`, `COUNTA`,
rounding, `ABS`, `IF`, `IFERROR`, `AND`, `OR`, `NOT`, `LEN`, `CONCAT`,
`CONCATENATE` and `&`. References may point to other sheets, including quoted
names and whole rows or columns. Range evaluation visits stored cells in
worksheet order and supports dependencies outside of the rendered window.
Conditional aggregates include `COUNTIF`, `COUNTIFS`, `SUMIF`, `SUMIFS`,
`AVERAGEIF`, `AVERAGEIFS`, `MINIFS` and `MAXIFS`. They accept single-area
references and names, with numeric comparisons, case-insensitive wildcards
(`*`, `?`, `~`) and blank criteria. Counts account for unstored blank matches
without expanding the range. Locale-specific date and numeric text criteria
remain limited.

Lookup formulas include `VLOOKUP`, `HLOOKUP`, `MATCH`, `XMATCH`, scalar
`XLOOKUP` and scalar `INDEX`. They accept cross-sheet ranges and defined names.
The lookup functions use typed keys and support exact, approximate and
case-insensitive wildcard matches where applicable. `XLOOKUP` and `XMATCH` also
support reverse search and binary search over sorted keys. An omitted `XLOOKUP`
key can match an unstored blank, and `if_not_found` is evaluated only on a miss.
`INDEX` can select a scalar from same-sheet reference areas. Spilled arrays and
reference-returning formula compositions remain limited.

Cached results remain authoritative. Shared formula followers use one master
definition per group and translate their relative references when evaluated.
Absolute references, quoted names and literals are preserved. Missing or invalid
definitions produce a worksheet warning. Defined names can be workbook-wide or
local to a worksheet, and support case-insensitive lookup, aliases, scalar
expressions and sparse multi-area ranges. Relative coordinates are resolved at
the formula cell. External references, unsupported functions and complete array
formula evaluation remain limited. Cyclic or unsupported formulas retain their
source text when available. Formula length, dependency depth and name expansion
are bounded for preview.

Numbers parsing also indexes merged ranges without creating blank covered-cell
objects. Its sparse model retains merge anchors, including those without row
storage, and actual stored continuation records; Pages keeps its dense grid.
Serialized ZIP/Snappy/IWA fixtures exercise 100,000 rows × 1,024 columns through
the real browser worker, and up to one million rows in the built parser under a
128 MiB Node V8 old-space cap. This bounds merge bookkeeping rather than total
archive/model memory: compressed/decoded data and source track arrays remain
resident. See [measurement scope](../../benchmarks/frontend/2026-11-25/numbers-merge-memory-review.json).

The current source API also accepts `controlsTarget` to place the existing
controls in an application header, including worksheet tabs, archive tools,
media controls, document attachments and the 3D inspector. Keep the target
mounted for the viewer's lifetime and load the runtime styles:

```js
const viewer = createPreview('#preview', {
  src: file, name: file.name,
  controlsTarget: document.querySelector('#preview-actions')
});
```

Style this host for your header's width and scrolling; driver controls retain
their actual DOM nodes and handlers. Fullscreen brings controls inside the
fullscreen preview and restores the header on exit. Destroying the viewer
removes its controls. This option is included in preview 0.3.7. Package and runtime measurements are
recorded separately in the linked build receipts.

Previews display a translucent `FiLens` watermark at the bottom right,
including when the toolbar is hidden and in preview fullscreen mode.

Split chunks can range from a few KB to hundreds of KB after compression. Those
figures exclude shared dependencies and engines; a chunk is not a complete
per-format download. The all-in-one file embeds CSS and document/image engines.
Deploy `archive/7zz.wasm` and the archive worker under `assets/` for RAR, 7z and
multi-volume ZIP. Deploy `xlsx/pcre2.wasm` for XLSX regular expression formulas.
Both builds include a separate notices file for redistribution. [Exact measurements](https://github.com/orca-zhang/filens/blob/main/docs/preview-build-sizes.json).

Single-file embedding still requires browser support for WebAssembly and workers.
Pages with a Content Security Policy must permit the generated inline styles,
`blob:` workers, and `blob:` / `data:` WASM connections. WASM compilation needs
`'wasm-unsafe-eval'`; packing adds no JavaScript `'unsafe-eval'` requirement.
Use an HTTP(S) server for module imports, rather
than opening the module-importing `index.html` as a `file:` URL. The CLI's
self-contained HTML embeds the module instead and supports `file:` URLs.
Hosted previews load these assets over HTTP(S). CLI exports from complete,
matching builds embed the assets for offline use.
The supported formats and fidelity
limits are shared with the [demo](https://github.com/orca-zhang/filens/blob/main/docs/support-matrix.md).

## Languages and application icons (0.2.0)

Preview toolbars, common prompts and model controls include the same 28 locale
codes as ZimaOS. Pass `locale: 'zh_CN'` (or `zh-CN`); omit it for browser language
detection. Switch language with `viewer.update({ locale: 'de_DE' })`. Optional
`messages: { Next: 'Forward' }` overrides English source phrases per instance.
Both split and all-in-one builds contain these dictionaries for offline use.
See the [locale list and API notes](../vue/README.md#languages-source-build).

APK/IPA packages open as ZIP-compatible archives with directory browsing and
entry previews. Windows EXE/DLL/MUI/MUN resource files can be previewed as
application icons using the included WASM converter. The converter also exposes
APK/IPA icon extraction for explicit requests. Icon extraction supports compiled
Android icon resources, XML/binary iOS plist metadata, iOS CgBI PNGs,
and Windows PNG/DIB icon frames. These additions are included in 0.2.0.
See the [supported icon representations
and limits](../vue/README.md#application-icons-source-build).

The browser file picker accepts multi-volume RAR (`.part01.rar` or `.rar`/`.r00`),
7z (`.7z.001`) and ZIP (`.zip.001` or `.z01`/`.zip`) archives. Select every part
together; picker order does not matter. Password prompts and nested previews
work across the parts. Missing first/intermediate volumes identify the filename;
the engine validates completeness. Limits are 256 parts and 512 MiB compressed
input per set, with 128 MiB per expanded entry. Both HTTP(S)-served builds support
this workflow with local archive sidecars; no remote service or CDN is used.
Programmatic callers supply the other
parts as `src.archiveVolumes: [{ name, source }]`; see the
[core API example](../core/README.md).

The split build loads `converter-office.wasm` only when an encrypted Office
document has a supplied password; a password prompt alone does not download it.
The all-in-one file includes the combined core with Office decryption,
PostScript and graphics conversion, avoiding duplicate WASI and parsing code.
Its static assets use independent LZMA groups; WASM is restored and then compiled
when first needed. HTTP split assets remain ordinary
WASM and use streaming compilation with the correct MIME. Historical core-only
comparisons are in the [same-source measurements](../../docs/converter-size-impact.md); current
main-runtime bytes are in `asset-packing.json` and the
[format package audit](../../docs/format-package-sizes.md).

## CLI preview

CLI 0.4.0 includes `preview`. The first preview downloads the optional frontend
package into the writable versioned cache; subsequent previews work offline.
You can install it ahead of time:

```sh
npm install -g filens-cli
filens setup-preview
filens preview report.pdf
filens preview report.pdf --no-open --json
```

`filens-cli-lite` supports the same preview command without OCR models. Frontend
resources are separate from the base CLI installation. For a source build:

```sh
npm run build:wasm
npm run build:agent:preview
npm run filens -- preview report.pdf

# Or run the freshly built binary directly
./dist/filens preview drawing.step
./dist/filens preview report.pdf --no-open --json
```

CLI 0.4.x used a loopback HTTP server. **CLI 0.5.0 defaults to a self-contained
HTML instead**: the shared all-in-one frontend runtime and a
copy of the selected file are embedded, the browser opens a `file:` URL, and the
CLI exits. No HTTP server is started. Parsing, conversion and rendering happen
in the browser, with no external runtime dependencies. The page checks WASM and
local Worker support and displays compatibility instructions on failure. It also
includes a GitHub link and third-party notices. Browser launch success does not
certify rendering; the CLI cannot automatically detect every browser failure.

```sh
# Generate and open an offline HTML, or save it without opening a browser
filens preview report.pdf
filens preview report.pdf --output report-preview.html --no-open
filens preview report.pdf --no-open --json

# Compatibility mode: serve only on this machine; Ctrl-C stops it
filens preview report.pdf --mode serve
```

HTML mode returns a `file:` URL and a filesystem `path`; the command exits even
with `--no-open --json`. Default HTML files remain in the system temporary
directory so the browser can finish loading after CLI exit. **The HTML contains
the original file bytes**; delete it when no longer needed. `--output` never
overwrites existing files. Base64 embedding adds about one third to the source
file size, plus the runtime and notices. Files over 768 KiB are embedded in
independent Base64 blocks that the browser assembles into a local File.
The HTML's Content Security Policy blocks external
connections and resource loads; linked images/fonts are unavailable unless
embedded or supplied locally. The GitHub link opens only when clicked.

On `file:` pages the embedded PDF.js module parses in a dedicated worker.
For large local PDFs, the page passes requested byte ranges to the worker and
paints the visible canvases. PDF.js can fall back to the main thread if the
browser blocks the local worker. HTTP mode uses the normal worker asset path.
On `file:` pages the iWork parser stays in a dedicated worker. For large local
files, the page keeps the File and sends the requested ZIP byte ranges to the
worker. The current build opens the tested Keynote, Pages and Numbers samples
offline in Chromium, Firefox and WebKit, including later-sheet media and an
encrypted Numbers file.

With both archive sidecars installed, the exporter adds their Base64 payloads
to each HTML, increasing its size by about 1.56 MB. The worker and WASM load on
demand when an archive needs them, including nested archives inside the selected
file. The CLI exports one source file, so a multi-volume archive should be
packaged into a single ZIP with all its parts. If the embedded engine is absent,
the preview displays the `--mode serve` fallback.

The exporter also embeds `xlsx/pcre2.wasm` when available, adding about 379 KB
of Base64. A workbook that uses `REGEXTEST`, `REGEXEXTRACT` or `REGEXREPLACE`
loads it on demand. If the asset is missing, the preview reports a workbook
warning and can still display saved formula results.

`--mode serve --no-open --json` retains the previous URL/server lifecycle. Its
command keeps running until Ctrl-C. `--port` implies serve mode unless an explicit
`--mode` is given. To choose a port or built runtime:

```sh
# Choose a port or another built runtime (including the all-in-one build)
filens preview report.pdf --mode serve --port 8080 --assets /path/to/preview/dist/all-in-one
```

`FILENS_PREVIEW_DIR` overrides the default `<binary-directory>/preview` asset
directory. An asset directory can be the package's `dist/` root or a specific
`split/` / `all-in-one/` directory; HTML mode needs the all-in-one runtime (a
`split/` directory also works when its `all-in-one/` sibling is present).
Source npm packaging can include the assets with
`node scripts/package-agent-npm.mjs --with-preview`. These optional resources
include both split assets and the all-in-one runtime, measured separately from
the document-reading CLI.

The server exposes one selected file, not its parent directory. Models or media
with external sidecars need a supported ZIP bundle or a host-provided resource
resolver; arbitrary adjacent files are not served. Binary media responses support
byte ranges. The listener checks the Host and Origin, scopes routes to a random
session path, and rejects directory traversal. CLI preview has been exercised on
macOS; Windows/Linux browser launching still needs native validation.
