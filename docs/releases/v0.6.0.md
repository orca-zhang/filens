### Browser and npm integration

The registry accepted `filens-preview@0.3.0` with HTTP 202 and is still processing
the upload. Until it becomes publicly available, install the exact tested tarball
directly from this Release:

```sh
npm install https://github.com/orca-zhang/filens/releases/download/v0.6.0/filens-preview-0.3.0.tgz
```

After npm processing completes, the versioned registry command is:

```sh
npm install filens-preview@0.3.0
```

Extract a browser ZIP and deploy the complete directory over HTTP(S), then open `index.html` to choose a local file. Applications can import `createPreview` from `filens.js`. Both builds now keep the optional archive engine and its worker as external files; retain `archive/7zz.wasm` and the worker under `assets/` for RAR, 7z and multipart ZIP.

[Preview API](https://github.com/orca-zhang/filens/blob/v0.6.0/packages/preview/README.md) · [Supported formats](https://github.com/orca-zhang/filens/blob/v0.6.0/docs/support-matrix.md).

### iOS and Android

- **iOS 15+ / Swift 5.9+:** extract the iOS ZIP, add `sdk/ios` as a local Swift Package and link `FilensPreview`. The package includes its offline runtime. Configure the local-network ATS setting documented in the integration guide.
- **Android 8+ / API 26+:** extract the Android ZIP and include `sdk/android/filens-preview` as an Android Library. JDK 17+, Gradle 8.9, Android SDK 35 and a current Android System WebView are required. The module can build an AAR; standalone AAR consumers also need AndroidX WebKit 1.12.1.
- Both hosts provide local file opening, language / toolbar options, render and error callbacks, source replacement and cleanup. iOS accepts local / security-scoped file URLs; Android accepts readable `content://` and `file://` URIs.

[SDK integration guide (Chinese)](https://github.com/orca-zhang/filens/blob/v0.6.0/sdk/README.zh-CN.md).

## Changes since v0.5.0

- Added the iOS and Android source preview SDKs with bundled offline resources and native lifecycle / message bridges.
- Added RAR / RAR5 and 7z previews, encrypted and solid archives, multipart RAR / 7z / ZIP, password retries, missing-volume diagnostics and nested entry previews. The extraction-only archive engine uses pinned 7-Zip source with O3 / LTO and shares compiled code across isolated operation workers.
- Added embedded Office attachment handling, shared ZIP readers and improved cancellation / nested-preview lifecycle behavior.
- Gzip-compressed embedded WASM before base64 and removed duplicate ZIP / compression loading from ordinary document paths. Main runtimes, optional archive sidecars and complete package downloads are now measured separately.
- Added the default translucent **FiLens © IceWhale** watermark, including preview fullscreen and hidden-toolbar layouts.

## Validation and limits

- The npm tarball passed isolated installation, TypeScript consumer checks, **48** real browser previews, native media / HEIF checks, and **12** PDF / iWork / RAW / STEP / HEIF / RAR previews after production Vite bundling. The registry accepted the upload; fresh-cache registry installation remains pending public availability. The Release tarball is the exact locally tested artifact, with its SHA-256 listed below.
- The mobile page and both native message shapes passed **22** Chromium / WebKit checks. Archive sidecars passed **12** browser checks covering ordinary ZIP, encrypted / solid / multipart archives, nested extraction and missing-volume errors.
- The iOS host passed **3** Swift loopback HTTP / path / byte-range tests and iOS Simulator arm64 compile checks. Android Java sources passed API 35 / AndroidX WebKit compilation and byte-range checks. Full Gradle AAR builds, simulator app execution and physical-device tests remain pending.
- These are read-only previews. Complex document fidelity, fonts, codecs, WebGL and device memory remain subject to the shared support matrix. Mobile SDKs currently accept one self-contained source; they do not expose native OCR, search, standalone conversion-result or multipart-file input APIs. Archive multipart support is available through the browser picker / frontend API.
