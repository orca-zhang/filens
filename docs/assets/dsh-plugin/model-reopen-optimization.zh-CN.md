# XLSX、iWork 与 STEP 重复打开优化

2026-11-05，未发布的 dsh-filens 0.1.3。与此前已完成 PDF 像素缓存、尚无模型缓存的
0.1.3 候选版配对测试：**9 轮、18 个独立 Desktop 进程、432 次实际打开**，
无失败、重试或删除样本。两版按轮交替先后顺序，测量期间不运行构建或其他测试。

| 文件 | 首开优化前 → 后（ms） | 重开优化前 → 后（ms） | 重开耗时减少 |
| --- | ---: | ---: | ---: |
| 小 XLSX | 109 → 107 | 68 → 68 | 未观察到稳定提升 |
| 大 XLSX，12,000 行 × 8 列 | 109 → 110 | 94 → 77 | 18.1% |
| Pages | 227 → 225 | 177 → 77 | 56.5% |
| Numbers | 193 → 227 | 176 → 93 | 47.2% |
| Keynote | 177 → 176 | 177 → 94 | 46.9% |
| STEP，法兰轴承 | 294 → 295 | 226 → 109 | 51.8% |

大 XLSX、Pages、Numbers、Keynote 与 STEP 在 **9/9 配对轮次**中重开都更快。
小 XLSX 为 4 轮更快、2 轮相同、3 轮更慢，不能声称这类小文件有稳定提速。
Numbers 首开增加 **34 ms（17.6%）**；保留独立解析快照有成本，首次打开并非全面提升。
STEP 首开有一次 377 ms 的离群值，已原样计入，没有排除。

## 复用了哪些工作

- XLSX 缓存解析后的单元格模型，跳过重复解包与 XML 解析。专用复制函数保留同一工作簿内
  的字体引用关系；每个标签获得独立单元格和字体，公式求值、字体映射不会污染下一次打开。
  原来的公开解析 API 保持每次解析，CSV 继续走直接解析路径。
- Pages、Keynote 缓存 worker 返回的解析模型，命中时不启动解析 worker。Numbers 仍只先解析
  第一张工作表；缓存命中后第一次切换到其他工作表时，新 worker 从保存的归档恢复上下文，
  再按需解析该表，不预解析全部工作表。
- STEP 缓存 WASM 导入后的 CPU 网格，跳过重复几何转换。每次重新创建 Three.js 几何、材质
  和场景，GPU 上传仍包含在耗时内；关闭一个标签不会释放另一个标签正在使用的资源。
  `loadStepObject` 的直接调用默认仍执行转换，预览会显式启用短期复用。

三类模型共享 **最多 4 条、64 MiB 估算模型预算、30 秒空闲过期**的 LRU。
64 MiB 是模型计费预算，不等于 JS 堆或整个预览的硬性内存上限；活动标签另有自己的模型。
完整字节 SHA-256 和解析类型/选项决定缓存键，同名文件修改内容后不会命中旧模型。
不保存 DOM、对象 URL、worker 或 GPU 对象，页面卸载时清空。缺少摘要或复制能力时正常解析。
密码打开跳过缓存，包括已经由共享转换器解密的 Office 文件；直接传入 URL 的读取路径不使用
模型缓存。若上层已读取为字节，则按完整内容校验，文件读取仍每次执行。

## 验证与复现

31 个相关 core 测试（缓存与加载生命周期）、83 个 XLSX、344 个 iWork、345 个 3D、
28 个 PDF、61 个 Vue、2 个 DSH 资源测试通过。浏览器验证 15 个独立格式加载路径和
12 类完整预览，另外实际验证 Keynote 缓存命中不再发送文档解析请求、Numbers 重开后仍可
按需解析第二张表且内容相同，关闭后 worker 数归零。Desktop 六类预览、布局、缩放及 3D
交互通过。本轮 Electron/macOS 的原生全屏退出自动化挂起，因此 Desktop 复跑显式跳过
原生全屏检查，未将它计为通过；浏览器全屏检查通过。

Apple M4 Pro，12 核、24 GiB，macOS 25.6.0；DSH Desktop 0.2.1-rc.5，Electron 44.7.0。
每版每轮启动新进程，按顺序打开六个文件，各打开 4 次，每次关闭标签。
首开取 9 次中位数，重开取后续 27 次中位数。起点在 `sidebar.openResource` 前，终点在
真实内容 ready 后再等两帧；包括文件读取、摘要、模型复制、布局、场景创建及 GPU 上传，
不含应用启动时间。后面的文件可能复用前面文件已加载的共享引擎。
系统文件缓存和应用持久缓存不清空；这是同机样例结果，不能外推所有文件和平台。

先运行 `node scripts/prepare-dsh-model-benchmark.mjs` 生成确定性的 96,000 单元格工作簿，
再用 `scripts/benchmark-dsh-model-reopen.mjs --home <隔离候选目录> --baseline-home <隔离基线目录>
--renderer filens|previous --rounds 1 --round-offset <0到8> --output <结果.json>`，
由外层每轮交替调用两个 renderer。保留原始日志，不在用户 profile 上运行。
