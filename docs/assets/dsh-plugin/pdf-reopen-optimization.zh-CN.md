# PDF 重复打开优化与复测

2026-11-05。当前未发布的 dsh-filens 0.1.3 已加入首张整页绘制结果复用。
同机将优化前后 0.1.3、公开 0.1.2 和 DSH 内置 PDF 放在同一轮次轮换测试，
**9 个完整配对轮次、36 次新进程启动、144 次实际打开**，无失败、重试或排除样本。

| 渲染器 | 首开中位数（ms） | 重复打开中位数（ms） |
| --- | ---: | ---: |
| 已发布 0.1.2 | 654 | 426 |
| 0.1.3 优化前 | 208 | 159 |
| 0.1.3 优化后 | 190 | 77 |
| DSH 内置 PDF | 329 | 110 |

相较同轮优化前 0.1.3，重复打开耗时减少 **51.6%**，首开减少 **8.7%**。
重复打开比同轮内置 PDF 少 **33 ms（30.0%）**。
首次打开每个文件仍需真正完成首张绘制，缓存仅适用于近期打开过且内容、尺寸一致的 PDF。

## 耗时来自哪里，做了什么

原来已经是虚拟渲染：ready 前只等首张，不等整份 PDF；其余附近页后台渲染。
但每次关闭再打开都会新建 worker，重新加载文档并重绘首张。
阶段跟踪中，PDF 元数据解析约 2 ms；首张图片、字体准备和绘制约 45–50 ms，
是主要的可复用工作。跟踪记录作为定位证据，未混入上面的正式计时。

现在只短时缓存**首张整页的独立像素副本**。每次仍创建自己的 PDF 文档和 worker，
成功读取文档与第一页后，才尝试恢复首张像素并报告 ready；无效 PDF 仍报错。
命中时绕过该页的图片/字体重复解码和绘制，实测像素复制约 1 ms。
另外，PDF 已完成绘制时，DSH 立即撤下加载遮罩，省去原先额外等待的一帧。

- SHA-256 覆盖完整文件内容；同名文件修改后不会显示旧画面。
- 缓存键包含精确 CSS 视口与 canvas 像素尺寸；缩放、窗口大小或像素密度不同会重新绘制，保持清晰度。
- 最多 4 张、共 16 MiB 像素；30 秒未使用后释放，淘汰时将画布清零，页面隐藏/卸载时清空。
- 密码打开、URL 来源和非虚拟打印/导出不使用缓存；没有可用的安全摘要或画布复制失败时正常绘制。
- 仅像素副本短时保留。关闭标签仍立即销毁文档、worker 和活动画布，多标签生命周期与控件独立。
