# ZIP 读取与加载优化

2026-11-04，本次改动统一 EPUB/CBZ、XMind/MindManager、VSDX 和 3MF 的 ZIP 读取路径，并简化 PPTX 的备用读取实现。解析仍在前端库中，后端转换边界不变。

后续轮次：[共享读取链路与压缩包交互优化](shared-readers-performance.zh-CN.md)，记录路径/ZIP/XML、键盘导航和 core/archive 发布包裁剪；下文保留此前测量。

- 这些格式复用核心的目录索引、按需解压、8 MiB 总缓存和单条目默认 128 MiB 上限。
- PPTX 不再为特殊压缩方法重新扫描整个 ZIP；不支持的附件只在读取该附件时失败。
- JSZip 兼容读取器按需导入，保留 ZIP64 和旧式 Unicode 元数据支持；加密 ZIP 继续使用现有密码读取路径。
- DOCX 打开时才导入 `docx-preview`，分包构建单独输出 DOCX 引擎及 ZIP 兼容读取器。公共浏览器占位模块留在共享分包，避免循环依赖。
- 原生大条目解压直接填充目标缓冲区，避免保留所有输出分片后再复制拼接。
- archive、diagram、books、iwork、mindmap、model3d、xlsx 共 7 个包的 JSZip 声明移至开发依赖，用于生成测试输入。JSZip 仍是核心兼容路径和第三方 DOCX 引擎的运行时依赖；这不代表移除了整个依赖树中的 JSZip。

## 实测

环境：Apple M4 Pro，Node.js v20.20.2。合成 ZIP 含 1,000 个 ASCII 路径的小 XML 条目，压缩后 146,802 字节，展开后 557,000 字节。两个实现交替运行，预热 3 次，取随后 7 次的中位数；校验每个条目的完整文本。读取时间不包含模块加载、网络、渲染和布局。

| 用例 | JSZip 3.10.1 | 共享读取器 |
| --- | ---: | ---: |
| 打开新归档并读取全部文本 | 65.64 ms | 2.07 ms |
| 再次读取已打开、已读取的条目 | 60.64 ms | 0.26 ms |

新归档用例约快 32 倍。共享读取器原本已用于部分格式，本次让更多格式复用它；这个比例不代表整个应用或完整预览提速 32 倍。Unicode 兼容路径、大图片、真实文件和不同浏览器需要单独计量。

独立 split 预览构建的入口及其递归静态导入 JS，对比基线提交 `66e01abbd36834ca20defc576ceb64d79efbd5b0`：

| 计量 | 基线 | 优化后 |
| --- | ---: | ---: |
| 原始字节 | 2,578,844 | 2,459,950 |
| gzip 字节 | 737,290 | 703,747 |
| Brotli 字节 | 623,510 | 594,944 |

gzip 启动 JS 减少 33,543 字节，约 4.5%。计量逐文件压缩求和，排除动态导入、Worker 和 WASM，实际传输取决于托管配置。DOCX 引擎与 ZIP 兼容读取器会在需要时下载；all-in-one 构建仍包含所有引擎。

## 验证

相关 9 个包的单元测试共 1,459 项通过、11 项跳过；浏览器回归 30 项通过，1 项真实 VSDX 语料测试因缺少外部语料跳过。覆盖 Unicode 路径、密码、未知压缩方法的未使用附件、大小上限、缓存取消、原生大条目解压及伪造大小。

split 和 all-in-one 均构建成功，并在 Chromium 中验证实际 DOCX、Unicode EPUB、销毁及资源释放。split 额外验证导入入口时不请求 DOCX 引擎和 ZIP 兼容分包，打开文档时正常加载。

修改涉及的源码通过类型检查；包含测试目录的 core 全量 TypeScript 检查仍在原有 `dom.spec.ts`、`viewer.spec.ts` 等文件中报错。转换策略与分类包边界检查通过。

## 第二轮：3D 引擎与 EPUB 资源按需加载

GLTF/GLB、OBJ、MTL、USDZ 和 LDraw 解析器改为在对应格式打开时动态导入，复用现有取消等待逻辑，保留现有异步调用方式。USDZ 增加可选取消信号，并从预览会话传入，避免取消后继续等待模块或执行解析。OBJ 只有实际解析到材质库时才加载 MTL 引擎。demo 和独立预览构建共用分包规则，避免共享 vendor 分包把这些解析器重新带入启动路径。all-in-one 仍内联全部引擎。

EPUB 清单只索引路径与媒体类型；图片、字体和样式在章节或 CSS 引用时才解压、生成 URL，并复用已经生成的 URL。删掉了提前解压所有清单资源的批处理和额外的展开字节缓存。仍会处理所有正文中的资源引用；此改动并未把章节解析改为翻页时执行。单元测试验证未引用图片及样式不被读取、跨章节重复图片只读取一次，并保留清单声明的 MIME 类型。

相同计量方法下，第二轮 split 启动 JS 如下；第一轮数字保留在上表：

| 计量 | 第一轮后 | 第二轮后 |
| --- | ---: | ---: |
| 原始字节 | 2,459,950 | 2,371,086 |
| gzip 字节 | 703,747 | 677,789 |
| Brotli 字节 | 594,944 | 573,852 |

本轮再减少 25,958 字节 gzip，约 3.7%；两轮累计相对原始基线减少约 8.1%。这是启动静态 JS 的减少，所需 3D 引擎仍在首次打开对应格式时下载，不表示完整预览时间同比下降。

第二轮验证：model3d 与 books 共 356 项单元测试通过，相关浏览器回归共 34 项通过。新增 GLB 和 USDZ 真实模块下载挂起测试，验证取消立即结束、其他调用能继续复用同一次下载。split、all-in-one 和 demo 生产构建通过；两种独立产物均在 Chromium 中打开 GLB、带材质的 OBJ、LDraw 和 USDZ，检查三角形数量及销毁。split 还验证启动不请求这五个解析器分包，打开对应格式后才请求。源码声明构建、转换策略与分类包边界检查通过。
