# XLSX 列格式解析优化

2026-11-04，优化前端 XLSX 解析库，未新增运行时依赖，公开接口保持不变。

此前只要工作表包含列声明和字体样式，就会退出数值/共享字符串快速解析，构建整张表的 XML 对象树；通用路径还会为每个单元格扫描列声明、重复转换范围边界。

现在复用原有 XML 解析器读取 `sheetData` 之前的元数据，含列格式的数值/共享字符串工作表也能直接生成预览数据模型。列范围只转换一次，按实际访问的列缓存首个匹配样式；不展开声明范围。行样式及行默认字体移出单元格循环。复杂 XML、富文本、公式和位于数据之后的列声明继续交给原有通用解析器，通用路径也复用列样式缓存。

字体优先级保持为：显式单元格样式 → 自定义行样式 → 首个匹配列声明 → 默认样式。显式样式 `0`、未设置样式的重叠列范围及无效字体索引保留原有语义。

## 实测范围

环境：Apple M4 Pro、Node.js v20.20.2。比较本轮修改前保存的 XLSX 构建产物与当前产物，复用同一 core 构建。每个合成工作簿为 2,000 行 × 64 列，共 128,000 个单元格，混合数值、共享字符串、显式单元格样式及自定义行样式。含列格式的用例有 64 条列声明。

两个实现交替执行，预热 2 轮、测量 7 轮，取中位数。计时覆盖完整 `loadXlsxWorkbook()`，包括 ZIP 索引、解压和工作簿数据模型解析；排除输入生成、模块导入、结果哈希、网络及渲染。每轮核对行列和单元格数量，完整模型 JSON 的 SHA-256 在两个实现及所有轮次之间一致。

| 用例 | 修改前 | 修改后 | 解析耗时变化 |
| --- | ---: | ---: | ---: |
| 无列声明的数值/共享字符串对照 | 55.0 ms | 54.6 ms | 基本持平 |
| 含列格式的数值/共享字符串 | 328.0 ms | 61.9 ms | 减少 81.1%，约快 5.3 倍 |
| 含列格式、强制使用通用解析 | 327.1 ms | 228.0 ms | 减少 30.3% |

最后一项通过给 `sheetData` 增加属性强制进入通用路径，数据内容相同；它用于隔离列样式缓存的收益，不能视为真实富文本工作负载。结果仅代表以上合成工作簿的解析耗时，不代表完整预览延迟同比下降，未测量峰值内存。

[机器可读结果与各次样本](../benchmarks/frontend/2026-11-04/xlsx-columns.json)保留输入归档、完整模型及参与测量的构建文件哈希。

## 复跑

```sh
npm run build:core
npm run build:xlsx
node scripts/benchmark-xlsx-columns.mjs
# 可选：与修改前保存的 XLSX dist 比较
node scripts/benchmark-xlsx-columns.mjs --baseline tmp/xlsx-columns-baseline/dist
```

基线目录需要包含修改前的 `index.js` 及其构建分包，并能解析到同一 core 依赖。应在修改源码前构建并复制保存；当前模式不需要基线。测量时不要同时运行构建或测试。

## 验证

XLSX 的 39 项单元测试及 4 项浏览器回归通过。新增覆盖列范围乱序及重叠、无样式范围优先匹配、显式样式 `0`、行样式覆盖、无效字体索引、超大列范围、属性实体引用、多个列容器、嵌套扩展元数据及数据之后的列声明，并核对快速/通用路径完整模型一致。

浏览器覆盖列格式工作簿的字体、共享字符串、100 → 200 → 240 行追加、公式、工作表切换、替换、取消及销毁。XLSX 声明构建、demo、split 和 all-in-one 生产构建通过；两种独立预览产物在 Chromium 中验证字体继承、滚动追加行、替换为 CSV 及销毁。转换策略、分类包边界检查及 `git diff --check` 通过。
