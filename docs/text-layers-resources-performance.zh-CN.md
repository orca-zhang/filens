# iWork 文本索引、CAD 图层与共享资源处理优化

2026-11-04，在 [PDF、共享字体与分类包体积优化](viewport-fonts-packaging-performance.zh-CN.md)后，继续处理 iWork、CAD 和多格式共用资源入口的规模开销。改动均在前端 TypeScript 内，没有新增依赖或后端解析算法。

## 实现与边界

- iWork 样式表本来已按字符位置排序。现在二分查找当前样式和段落内的变更范围，避免每段、每个文本片段反复扫描全表；段落样式在建表时记录前一个有效引用，连续空样式条目仍继承此前的段落样式，字符样式的空条目仍重置样式。重复位置仍按原顺序取最后一条。短表使用顺序查找，无字符样式时直接构造文本片段；有序边界直接去重，省去每段的 Set 和排序。含 NaN 的畸形表保留原有前缀扫描和边界排序行为。
- Pages 布局提示和内联附件按字符位置查段落时，利用有序段落范围二分查找，保留段首、段尾、空文本、越界位置和 NaN 的原有结果。这只优化定位，不改变分页、几何或附件布局规则。
- CAD 在渲染文档时建立已知图层集合，批量选择和逐个切换时按集合验证图层名称。替换、失败、取消和销毁时清理集合；字体更新引发重绘时重新建立。去重后的选择顺序、未知图层处理、实体自身隐藏标志及状态事件保持原样。全量选择、状态数组创建和可见性检查仍需要遍历相关图层。
- 共享上传资源索引复用规范化文件名、根目录前缀和 basename 候选表，删除临时别名 Set、过滤数组和候选表副本；basename 使用字符串位置截取，无百分号的路径片段跳过 URL 解码。精确路径、根目录别名、唯一 basename 的匹配顺序，以及重复 basename 的歧义规则保持原样。点路径处理仍发生在逐段 URL 解码之前，没有跨调用缓存。

样式索引新增每条样式的继承引用元数据，CAD 新增 O(图层数) 的名称集合。均随当前文本框或当前文档释放；本轮没有测量峰值内存。

## 浏览器对照

Apple M4 Pro、Node.js v20.20.2、Chromium 147.0.7727.15。保存修改前的四份源码，以相同 esbuild 配置和相同当前依赖构建两份运行模块；预热两轮，交替测量七轮，以下为中位数。计时期间没有并发构建或测试。输入构造、模块导入、序列化、完整输出哈希比较都在计时外。

| 场景 | 修改前 | 修改后 |
| --- | ---: | ---: |
| 6,000 段文字、18,000 条字符样式，完整文本框构建 | 284.80 ms | 14.20 ms |
| 单个长段落、18,000 条字符样式，完整文本框构建 | 123.80 ms | 8.60 ms |
| 6,000 段无样式文字，完整文本框构建 | 2.70 ms | 2.10 ms |
| 12 段带样式文字，文本框构建 × 100 | 2.30 ms | 2.30 ms |
| 6,000 段文字、500 页布局提示，完整 Pages 文档构建 | 12.80 ms | 6.90 ms |
| 30,000 个段落范围、6,000 组成对段首/段尾查询 | 143.00 ms | 2.80 ms |
| 1,024 个 CAD 图层，12 次选择/切换 | 4.80 ms | 1.20 ms |
| 4,096 个 CAD 图层，12 次选择/切换 | 61.50 ms | 5.70 ms |
| 30,000 个普通路径资源，完整索引构建 | 52.00 ms | 24.00 ms |
| 10,000 个含 URL 编码名称的资源，完整索引构建 | 16.90 ms | 11.00 ms |
| 12 个资源，索引构建 × 100 | 1.60 ms | 0.70 ms |
| 已有索引上查找 30,000 个资源路径 | 24.80 ms | 14.60 ms |

另有 16 图层小用例，两者均不超过 0.1 ms；原始零值采样保留在结果中，不据此计算倍数。小于 1 ms 的测量受计时分辨率影响。

CAD 计时覆盖图层 API 内的名称验证、状态创建、SVG 属性修改和事件发出，不包括 DXF 解析、初始 SVG 构造或下一帧绘制；每次运行比较操作序列的完整活动图层状态及最终 SVG。资源查找计时包含路径规范化和 Map 查询，不包含资源下载或图片解码。文本框/文档构建和独立段落定位分别计时，不能把定位收益当作整个预览的收益。

首次测量发现空样式文本和小文本框有额外开销，随后增加短表、无字符样式及有序边界快速路径。上表使用最终实现，保留小文档对照。

## 运行资源体积

使用各包现有 Vite 配置、相同依赖，分别将原源码和当前源码用于主线程及 Worker 构建。只统计生成的 JS/CSS，排除声明和源码映射。当前所有输出文件的 SHA-256 均与实际包 dist 一致；gzip 为逐文件压缩后的大小之和，不是 npm tarball 或完整安装体积。

| 包 | 原始字节：前 → 后 | gzip 字节：前 → 后 |
| --- | ---: | ---: |
| core | 521,994 → 521,950 | 122,689 → 122,696 |
| cad | 75,769 → 75,771 | 19,327 → 19,326 |
| iwork（含 Worker） | 1,811,999 → 1,813,495 | 343,482 → 344,056 |
| 合计 | 2,409,762 → 2,411,216 | 485,498 → 486,078 |

本轮运行资源净增 1,454 字节，gzip 净增 580 字节（约 0.12%）；增加主要来自 iWork 的范围索引和快速路径在主线程、Worker 两份构建中出现。本轮没有进一步缩小发布包；此前排除源码映射的发布规则继续生效。

## 验证与复现

- 995 项单测通过：core 448、iWork 340、CAD 65、EPUB 37、3D 资源/取消相关 105；另有 11 项既有外部对照测试跳过。增加了重复/乱序/畸形样式、可变 UTF-16 段落边界、资源别名与歧义、图层替换和销毁的回归。
- 21 项浏览器回归通过，覆盖 CAD 栅格资源和图层切换、iWork 原生 Worker 与上传、OBJ 纹理及上传、EPUB 样式与字体。初次 EPUB 上传测试因文件选择器匹配两个控件失败，限定到 `.wb-upload` 后两项 EPUB 测试通过；CAD 上传测试同样限定实际上传控件。
- 13 组性能输入的每次输出均一致；另比较了 61 组段落边界结果、256 组含乱序/重复/NaN/无穷位置的样式输入、225 次包含畸形编码与歧义的资源查询。
- 六个真实 iWork 样例的完整模型 JSON 一致：demo 的 Pages、Numbers、Keynote，以及第三方测试数据各一份。真实样例用于兼容性验证，没有据此宣称加载时间收益。
- core、CAD、iWork 正常构建通过。对照脚本、输入样例、源码、运行模块、依赖和产物的哈希均已核对。
