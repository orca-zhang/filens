# PDF 可见页、共享字体与分类包发布体积优化

2026-11-04，在[EPUB、思维导图、Visio 与 3D 资源优化](document-resources-performance.zh-CN.md)后，将性能范围扩展到 PDF 和共享字体链路，并继续裁剪另外 15 个前端包的 npm 发布体积。没有新增依赖或后端解析/转换算法。

## 实现

- PDF 页槽按垂直位置有序排列。滚动时通过实际 DOM 几何二分定位附近页，再检查可见范围及相邻页；保留混合页高、页间空隙、边界相交、低缩放和最大重叠页的选择规则。几何查询从逐页扫描变为 O(log n + k)，k 为附近页数。缩放和首次布局仍需设置所有页槽尺寸。
- PDF 用集合跟踪有画布或渲染任务的页槽，只遍历这些页来释放远处画布、取消任务及销毁文档。页切换和缩放期间仍按已有代次检查忽略旧结果。
- 共享场景字体收集按原始字体字符串复用规范化结果；加载引用按字体和六种粗体/斜体状态复用结果。达到原有 4,096 个 UTF-16 码元的采样上限后停止拼接，保留原始字体、字形状态、文档顺序和截断位置。
- 字体诊断在单次调用内复用相同字体、相同 traits 对象的分类计算；输出分类对象保持独立。缓存不跨调用保留，后续字体安装、traits 修改与文档替换仍重新检查。这条链路供 PPTX、iWork、CAD、DOCX 等格式使用。
- 15 个包使用隐藏 JS 源码映射、本地保留映射文件，发布 files 规则排除 dist 下的映射；关闭声明映射，避免生成失效引用。媒体包复制第三方类型文件时移除已有的失效映射尾注；Vue 声明保留 @filens/media 包名，修复指向仓库兄弟目录的导入。第三方源码快照未改动。

## 浏览器性能对照

Apple M4 Pro / Node.js v20.20.2 / Chromium 147.0.7727.15。对修改前保存的三份实现源码与当前实现，用相同 esbuild 参数、相同当前依赖分别打包。预热 2 轮，交替测量 7 轮，以下为中位数。输入构造、模块导入、滚动/初始布局准备、序列化和完整输出哈希比较都在计时外；每轮输出一致。

| 场景 | 修改前 | 修改后 |
| --- | ---: | ---: |
| 100 页，40 次可见页查询 | 1.20 ms | 0.20 ms |
| 2,048 页，40 次可见页查询 | 22.10 ms | 0.30 ms |
| 10,000 页，40 次可见页查询 | 108.40 ms | 0.30 ms |
| 30,000 段文本，字体诊断引用收集 | 1.60 ms | 0.80 ms |
| 30,000 段文本，字体加载引用收集 | 20.20 ms | 0.50 ms |
| 10,000 条重复字体引用，完整字体诊断 | 11.40 ms | 3.20 ms |
| 24 段文本，加载引用收集 × 100 次 | 0.20 ms | 0.10 ms |
| 1,000 种不同字体，引用收集 × 10 次 | 1.00 ms | 1.20 ms |
| 200 种不同字体，完整诊断 × 5 次 | 60.10 ms | 55.70 ms |

PDF 输入是生成的 80/800/1,600 px 混合页高 DOM，时间只覆盖 40 次可见页选择，不包含 PDF 解码、初次布局、完整滚动帧或绘制。另对真正的 100 页混合页高 PDF，比较五组导航、缩放/适配、完整像素 SHA-256、画布数量和销毁行为，结果一致。活动画布集合通过生命周期回归验证，没有单独计时。

字体重复用例包含八种字体和六种字形状态；它们用来观察大量重复文本的收益。全部字体都不重复时，缓存没有同样的收益：1,000 种字体的引用收集从每十次 1.00 ms 变为 1.20 ms。不同字体的完整诊断主要受 canvas 字体探测影响，多轮运行有波动。小于 1 ms 的结果受浏览器计时分辨率影响，保留原始零值采样，不据此推算完整预览倍数。没有测量峰值内存。

## 复跑

先按项目构建流程生成依赖与分类包 dist，并安装 Playwright Chromium。将归档解压到临时路径，不要覆盖工作区源码。性能脚本只需要源码基线；打包脚本的 control-only 模式使用当前 dist，无需历史构建。

```sh
mkdir -p tmp/viewport-fonts-baseline
gzip -dc benchmarks/frontend/2026-11-04/viewport-fonts-source-baseline.json.gz > tmp/viewport-fonts-baseline/sources.json
node scripts/benchmark-viewport-fonts.mjs
node scripts/verify-category-package-maps.mjs --control-only
npm exec --workspace @filens/core -- vitest run --maxWorkers=4 --minWorkers=1
npm exec --workspace @filens/pdf -- vitest run --maxWorkers=4 --minWorkers=1
npx playwright test apps/demo/e2e/pdf-lifecycle.e2e.ts apps/demo/e2e/pptx-lifecycle.e2e.ts apps/demo/e2e/iwork-lifecycle.e2e.ts --workers=1
```

测量期间不要并行构建或测试。打包验证会在 tmp 中生成与解包 tarball，不会发布或安装包；若需要历史构建比较，应在修改源码和配置前另存 dist 快照。
