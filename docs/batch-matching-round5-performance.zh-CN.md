# 批量匹配第五轮：按需提取文件名词频

2026-11-04，接续[第四轮](batch-matching-round4-performance.zh-CN.md)，优化共享 Rust/WASM 搜索核心的文件名词频表。实现位于 [search.rs](../wasm/converter-core-rust/src/text/search.rs)，未增加运行时依赖。

后续：[第六轮：先选择文件，再排序摘录](batch-matching-round6-performance.zh-CN.md)，减少大量命中时的完整排序与文件计数开销。

## 实现与语义

原实现会在评分前给全部源文件的名称分词，并保留全部词频表。BM25 模式下，正文为空的文件不会产生结果块；超过 65,536 块上限后的文件也不会进入检索，但它们的名称仍会被分词。文件名模式还会把名称词频复制到另一个空词频表中。

现在按结果块的文件顺序，缓存当前文件的名称词频。只有实际进入特征提取的文件才会触发名称分词；切换文件时释放旧表。名称词频按原规则封顶为 2，BM25 模式把封顶后的值加入正文词频；文件名模式直接借用名称词频表，避免复制字符串与树节点。精确模式不调用这条分词路径。

完整词频表仍按字典顺序计算文档长度，查询特征与评分顺序保持不变。文件名短语判断沿用上一轮实现；命中门槛、排序、来源位置、渲染、总文件数、结果块上限和截断标记没有改动。空正文的 BM25 文件仍不因名称命中而生成结果块。

8 MiB 查询特征预算保持不变。超预算块在评分时会再次提取特征，此时也可能再次给该文件名分词；每次顺序遍历仅保留当前文件的词频表，以这部分重新分词换取较低的常驻表数量。该缓存不是整次搜索的内存上限。

## 测量方法

Apple M4 Pro、Node.js v20.20.2，通过前端真实的 `InMemoryWasiHost` 运行生产 `converter-text.wasm`，每次操作创建新实例。计时包含实例创建、内存文件读取、JSON 解析、搜索评分、序列化和结果写入；编译、host 初始化、输入生成、结果读取、断言和哈希在计时外。预热 3 轮，测量 9 轮，前后版本交替执行，取中位数。所有计时轮次均检查完整响应哈希。

线性内存取完整操作后 `memory.buffer.byteLength`，单位 MiB。WASM 线性内存只增长、不缩小，因此该指标反映其增长高水位，不代表存活堆对象、物理驻留内存或整个 Node 进程的 RSS。本轮不包含浏览器界面、文件提取、OCR 推理、磁盘读写或 CLI 启动耗时。

## 性能

| 用例 | 修改前 | 修改后 | 加速 |
| --- | ---: | ---: | ---: |
| 英文 BM25，32 文件 | 1.041 ms | 1.080 ms | 0.96 倍 |
| 英文 BM25，1,000 文件 | 13.76 ms | 13.72 ms | 基本持平 |
| 64 个长文件，深层目录，文件名短语命中 | 127.04 ms | 127.65 ms | 基本持平 |
| 同上，文件名短语不命中 | 127.67 ms | 130.63 ms | 0.98 倍 |
| 中文 BM25，64 文件 | 133.47 ms | 131.45 ms | 1.02 倍 |
| 16 查询词、64 文件 | 85.41 ms | 86.67 ms | 0.99 倍 |
| 文件名搜索，1 万英文名称 | 34.43 ms | 31.40 ms | **1.10 倍** |
| 文件名搜索，1 万中文深层路径 | 472.82 ms | 428.79 ms | **1.10 倍** |
| BM25，1 万中文深层路径，正文均为空 | 346.66 ms | 21.51 ms | **16.11 倍** |
| 字面精确搜索，1 万文件，对照 | 16.04 ms | 16.13 ms | 基本持平 |
| 16 查询词、6,400 块 | 212.35 ms | 213.80 ms | 0.99 倍 |
| 64 查询词、10,240 块，查询特征缓存超限 | 489.88 ms | 494.17 ms | 0.99 倍 |
| 128 查询词、仅两词命中，64 文件 | 26.98 ms | 27.64 ms | 0.98 倍 |

主要收益集中在文件名搜索与未产生结果块的文件。16.11 倍对应正文全部为空、共 0 块的特定场景，不能推广为有正文的 BM25 搜索加速。普通 BM25 本轮没有普遍提速：32 文件用例增加约 0.039 ms、3.7%，其他 BM25 用例的耗时变化约为 −1.5% 至 +2.5%。表中保留这些回退结果。

## 内存与取舍

| 用例 | 修改前 | 修改后 | 变化 |
| --- | ---: | ---: | ---: |
| 文件名搜索，1 万英文名称 | 14.188 MiB | 14.188 MiB | 不变 |
| 文件名搜索，1 万中文深层路径 | 38.375 MiB | 28.313 MiB | **−10.063 MiB，约 −26%** |
| BM25，1 万中文深层路径，正文均为空 | 35.875 MiB | 28.313 MiB | −7.563 MiB，约 −21% |
| 文件名搜索，65,538 文件、截断为 65,536 块 | 79.750 MiB | 79.750 MiB | 不变 |
| 16 查询词、6,400 块 | 12.063 MiB | 12.188 MiB | +0.125 MiB |
| 64 查询词、10,240 块 | 23.375 MiB | 23.375 MiB | 不变 |

减少词频表分配不保证所有输入的线性内存高水位都下降。源数据仍会完整解析，查询特征和结果块等结构仍需空间；短英文名称与截断用例的高水位没有变化，6,400 块用例增加 128 KiB。本轮保留这些取舍。

## 验证

- 13 项共享搜索源码测试通过。新增测试验证中文与英文文件名重复词的频率封顶、文件名模式忽略正文、相对路径为空时的名称回退，以及文件名词频与正文词频相加；0、128 字节和默认查询特征预算产生相同结果。
- 36 组本轮生产 WASM 完整响应对照通过，包括万条中文深层路径、空正文与非空正文交替、重复文件名词、65,536 块上限后的未搜索文件，以及原有 Unicode、稀疏特征、缓存超限、5 种输出格式和来源信息用例。
- 24 组精确搜索与 Office 媒体操作、5 组 OCR 响应对照再次通过，合计 **65 组完整响应对照**。仅忽略 `metrics.elapsedMs`，评分等字段严格比较；OCR 推理使用固定 host 响应，生产解析、过滤和来源映射实际执行。
- 转换架构边界检查 2,122 项通过。
