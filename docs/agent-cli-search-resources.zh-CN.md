# 搜索运行时间与内存

本轮调整 FiLens CLI 的构建和提取调度，保留共享核心中的解析、分块、评分、原文定位与导出算法。

- `filens-cli` 包的 release 优化级别设为 `3`；依赖仍按 `z` 缩小体积，保留 LTO。
- 并行提取按路径顺序分配窗口，按输入元数据估算每窗最多 4 MiB，并根据剩余语料预算收紧。一个大文件可以独占窗口，零字节文件也受数量限制。
- 完成并合并当前窗口后才处理后续路径；达到预算后停止调度。窗口之间复用运行时，并继续共享正文 WASM 模块和保留独立 OCR 通道。
- 保留跨越预算的压缩包结果，语料组装时仍可纳入其中能够容纳的成员。结果路径顺序与线程完成顺序无关。

2026-11-23，macOS arm64，本机 release CLI。每个场景先各预热一次，再交替运行五对新进程；没有应用索引或缓存，操作系统页缓存保持启用。下表为完整进程耗时中位数，不代表物理冷盘性能。

| 合成场景 | 优化前 | 优化后 |
| --- | ---: | ---: |
| 英文 BM25，2000 个文件、约 15.65 MiB | 417.00 ms | 124.67 ms |
| 中文 BM25，128 个文件、约 2.34 MiB | 186.42 ms | 50.07 ms |
| 精确搜索，2000 个文件、四线程 | 32.78 ms | 30.09 ms |
| 超预算精确搜索，256 × 512 KiB、四线程 | 44.93 ms | 39.77 ms |

英文 BM25 排名阶段从 381 ms 降至 90 ms；中文从 175 ms 降至 40 ms。20 对测量均检查结果、分数、排序、正文摘录、命中文件数与分块数一致。

超预算场景最终均纳入相同的 64 个文件、32 MiB 语料，实际读取文件从 256 个降至 65 个。另行运行 `/usr/bin/time -l`，该场景的进程 RSS 单次观测为 **138.27 → 42.55 MiB**；这不是内存分布或内存硬上限。CLI 二进制体积为 **2.25 → 3.74 MiB**，是此次速度优化的代价。

完整样本、二进制哈希和阶段耗时见 [JSON 记录](agent-cli-search-resources.json)。复现时，先分别保存优化前、后的 CLI，再运行：

```sh
node scripts/benchmark-search-resources.mjs \
  --baseline /path/to/before/filens \
  --binary /path/to/after/filens \
  --output docs/agent-cli-search-resources.json
```

功能回归覆盖四线程、八线程预算停止、压缩包成员前缀、多窗口 WASM 运行时复用，以及小批量文档默认串行。Windows x64 通过交叉编译检查，尚未实机验证。没有在本轮运行 OCR 或测量物理冷盘；大文本仍完整读取后解码，压缩文档膨胀和单个大结果仍可能突破窗口的输入大小估算。
